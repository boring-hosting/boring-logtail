#+title: boring-logtail roadmap
#+license: GFDL-1.3-or-later

The capture source of truth is the CRI record committed below =/var/log/pods=.
Logtail reads node-local files and ships bounded batches. The collector owns
stateless ingestion and typed reads; Loki owns seven-day history.

* Node capture

- [X] Parse opaque CRI stdout/stderr records and bounded =P=/=F= partials.
- [X] Start existing files at EOF, follow append, and handle inode rotation.
- [X] Read notified files directly; debounce lifecycle reconciliation and keep
  a slow repair scan.
- [X] Enrich by exact Pod UID and container name from a node-scoped watch.
- [ ] Measure long-running CPU, RSS, missed bytes, duplicates, notification
  overflow, and reconciliation activity.
- [ ] Add persisted offsets only if restart-loss measurements justify them.

* Delivery and collection

- [X] Keep node delivery bounded by records, bytes, time, and retry duration.
- [X] Put bulk writes and retained/live reads behind storage ports.
- [X] Preserve opaque bytes and explicit integrity through OTLP.
- [X] Replace process-local history with the Loki storage adapter.
- [X] Reduce operator configuration to demonstrated product choices.
- [ ] Add another OTLP signal only when its backend and use are concrete.

* Queries and consumers

- [X] Stream retained tail followed by matching live inserts over gRPC.
- [ ] Authenticate, authorize, and encrypt the collector stream before exposing
  it outside trusted cluster wiring.
- [ ] Replace the web backend's Kubernetes Pod-log adapter with the collector.

* Release gates

- [ ] Every loss boundary has a counter or integrity marker.
- [ ] Sustained throughput, burst, backpressure, restart, rotation, and metadata
  delay checks pass at documented bounds.
- [ ] Ordinary builds and images require stable Rust only.

* Retired experiment

The eBPF =write=/=writev= scraper was removed from the active workspace after
the CRI boundary passed live comparison. Its code remains in Git history and
its lessons remain in =learn/ebpf.org= and the retrospective under =blog/=.
