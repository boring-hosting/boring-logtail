This file indexes deliberately deferred work and ideas worth revisiting. Active
execution steps belong in the TODO section of their corresponding file under
=spec/=.

* TODO Add measured CRI-O cgroup and log-layout support

Why: both live nodes run CRI-O 1.33, and the first enrichment join deliberately
rejects that currently unsupported layout instead of guessing. See
=spec/20260802-0743-kubernetes-identity-enrichment.org=.

* TODO Revisit crate boundaries after enrichment responsibilities settle

Why: Linux capture, cgroup/runtime discovery, and Kubernetes-shaped identity
may deserve separate crates, but splitting them before their interfaces have
survived real use would freeze guesses. See
=spec/20260802-0743-kubernetes-identity-enrichment.org=.

* TODO Prototype userspace-fed inode filters for CRI log writes

Why: a VFS/file-write adapter could capture already-framed Kubernetes logs with
zero additional filesystem I/O per record while userspace controls fixed-size
device/inode map entries.

* TODO Revisit a VFS CRI-file adapter when Rust emits proven CO-RE field relocations

Why: the 2026-08-02 fexit experiment compiled kernel-struct field access as
literal development-layout offsets; object inspection found no CO-RE field
relocations. See =spec/20260802-0928-userspace-registered-cri-log-tap.org=.

* TODO Measure lifecycle races for dynamically registered log files

Why: creation, first write, rotation, deletion, agent restart, and inode reuse
can race userspace map updates; the prototype needs evidence before replacing
the generic application-write path.

* TODO Remove konnectivity packet tracing from ordinary cluster operation

Why: both node agents run with =-v=8=; following boring-logtail through
=kubectl logs= creates a cross-cgroup observer loop because konnectivity logs
the traffic used to transport collector output.
