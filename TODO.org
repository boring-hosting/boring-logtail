This file indexes deliberately deferred work and ideas worth revisiting. Active
execution steps belong in the TODO section of their corresponding file under
=spec/=.

* TODO Revisit crate boundaries after enrichment responsibilities settle

Why: Linux capture, cgroup/runtime discovery, and Kubernetes-shaped identity
may deserve separate crates, but splitting them before their interfaces have
survived real use would freeze guesses. See
=spec/20260802-0743-kubernetes-identity-enrichment.org=.

* TODO Remove konnectivity packet tracing from ordinary cluster operation

Why: both node agents run with =-v=8=; following boring-logtail through
=kubectl logs= creates a cross-cgroup observer loop because konnectivity logs
the traffic used to transport collector output.

* TODO Design safe eBPF filter pushdown from positive exclusion evidence

Why: absence from an included-namespace-only Pod cache may be cache lag, not an
excluded workload; denying that cgroup would silently lose startup writes. See
=spec/20260805-1655-declarative-capture-filters.org=.

* TODO Give Kubernetes watcher tasks explicit application ownership

Why: process exit currently tears down the detached tasks, but explicit handles
would make graceful shutdown testable. See
=spec/20260805-1655-declarative-capture-filters.org=.

* TODO Separate scoped-filter exclusion from genuine identity-resolution loss

Why: an included-namespace-only Pod cache intentionally makes excluded
workloads look unresolved, while metadata lag can produce the same outcome; one
counter cannot diagnose both. See
=spec/20260805-1655-declarative-capture-filters.org=.

* TODO Design the authenticated external streaming protocol

Why: the bounded store defines an internal replay-watermark/live-receiver
contract, but transport, selectors exposed to users, authorization, and wire
backpressure need their own threat model. Store selectors are workload, Pod,
and namespace identity; the external representation is still undecided. See
=spec/20260809-1905-workload-store-product-contract.org=.

* TODO Add durable replay cursors only with persistence and acknowledgements

Why: process-local sequence numbers can make one connected replay/live handoff
gap-free, but cannot provide exactly-once reconnects or survive agent restart.
See =spec/20260809-1626-bounded-replay-log-store.org=.

* TODO Design event message capture interpolation

Why: ={1}= looks tiny but needs honest missing-group, escaping, byte-to-text,
and secret-leak semantics. Static messages ship first. See
=spec/20260812-1405-lean-config-event-catchers.org=.

* TODO Allow several destinations of one emitter kind

Why: the lean key-selected configuration supports one stdout and one Discord
destination today; do not invent nesting until a real second destination is
needed. See =spec/20260812-1405-lean-config-event-catchers.org=.
