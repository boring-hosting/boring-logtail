#+title: The BLT crate map
#+license: GFDL-1.3-or-later

BLT is two programs assembled from a few Rust crates. Arrows mean “depends on.”

#+begin_example
boring-logtail -> blt-model <- blt-otel -> boring-collector
                                             /          \
                                      blt-store      blt-emitter
#+end_example

* =blt-model=

Shared userspace facts: log records, integrity, Kubernetes identity, and caught
events. It owns no watchers, queues, storage, regexes, or network clients.

* =blt-otel=

The byte-preserving bridge between =LogRecord= and OTLP Logs, plus the node's
bounded batch and retry worker. OTLP is ingestion, not querying.

* =blt-store=

The collector's bounded in-memory log database. Ingestion appends immutable
records while API readers query, clear, or follow the same shared store.

* =blt-emitter=

Bounded delivery actors for caught events. A slow destination can fill its own
queue; it cannot apply network backpressure to capture.

* The binaries

=boring-logtail= owns CRI-file lifecycle, partial joining, Kubernetes watches,
and collector delivery. =boring-collector= owns retention, policy, catchers,
emitters, and gRPC reads.

Put code with the facts or resource lifecycle it owns. Leave a moving boundary
in its composition root until evidence earns another crate.
