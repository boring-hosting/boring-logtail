#+title: Runtime self-observability
#+date: 2026-10-13 08:27 UTC
#+license: GFDL-1.3-or-later

* Status

Accepted on 2026-10-13.

* Context

=boring-probe= already publishes kubelet CPU and memory measurements for nodes,
Pods, and containers. Those resource metrics describe workloads, including the
three boring-logtail programs, but they do not explain whether capture,
delivery, snapshotting, or Loki export is healthy.

Logtail already holds useful file, partial-record, integrity, and OTLP export
statistics and prints them once per minute. They are not queryable or suitable
for alerting. Probe logs one result per snapshot but records no duration or last
success. Collector exposes only =/healthz= and does not measure OTLP or Loki
behavior. Prometheus already discovers explicitly annotated Service endpoints.

The missing signals are process self-observability, not another Kubernetes
resource collector.

* Decision

Add a private =RuntimeMetrics= module inside each program package using a typed
Prometheus registry. Each module owns metric registration, observation, and
text encoding behind domain-specific methods. Pass its clone into the loops and
adapters that own the measured events. Do not add a metrics trait, a shared
workspace crate, a global recorder, or an OTLP self-export pipeline: there is
one concrete registry implementation and Prometheus scraping is already live.

Expose Prometheus text at =/metrics= and explicit liveness/readiness endpoints
at =/healthz= and =/readyz=. Collector serves all three on port 13133. Logtail
and probe add a strict =http_listen= configuration, defaulting to
=0.0.0.0:9090=, and run a small HTTP server under their existing application
lifecycle and graceful shutdown.

=/healthz= reports whether critical runtime tasks remain alive. =/readyz=
becomes successful only after configuration, listeners, capture/watch state,
and the application loop are initialized; it returns unavailable during
shutdown or after a critical task exits unexpectedly. Neither endpoint probes
Loki, Prometheus, the kubelet, Kubernetes, or the collector. Transient
dependency failures must not cause restart or rollout flapping; counters and
last-success metrics expose those failures instead. Kubernetes startup,
readiness, and liveness probes use these endpoints.

Instrument this first contract:

| Program   | Kind      | Signal |
|-----------+-----------+--------|
| logtail   | gauge     | tracked CRI files and actually buffered file bytes |
| logtail   | gauge     | pending partial lanes/bytes and known identities |
| logtail   | gauge     | current OTLP queue records/bytes |
| logtail   | counter   | captured, exported, and integrity-marked records |
| logtail   | counter   | dropped records by bounded reason |
| logtail   | counter   | export batches, retries, failures, and watcher overflows |
| logtail   | histogram | filesystem reconciliation and OTLP export duration |
| probe     | gauge     | Pods and containers in the last snapshot |
| probe     | gauge     | last successful reconcile Unix time |
| probe     | counter   | reconciles by =success=, =read_error=, or =push_error= |
| probe     | histogram | kubelet read and Prometheus push duration |
| collector | gauge     | in-flight Loki exports |
| collector | counter   | OTLP requests/records by bounded result |
| collector | counter   | Loki concurrency saturation and export failures |
| collector | histogram | Loki export duration |

Use the =boring.logtail.=, =boring.probe.=, and =boring.collector.= namespaces.
Follow OpenTelemetry instrument naming: dot-separated names describe the
quantity without encoding units or instrument types (for example,
=boring.logtail.export.duration=). The Prometheus text Adapter translates dots
to underscores and its encoding adds =_total= to counters. Labels are limited to fixed
enums such as =reason= or =result=. Never label self-metrics with a file path,
Pod UID, Pod/container name, namespace, workload, error message, endpoint, or
HTTP status text. Prometheus discovery supplies target identity; this keeps the
application metric cardinality constant as workloads grow.

Change =CriFileStats.pending_bytes= to sum the current pending buffer lengths,
not allocated vector capacity, before exporting it as a gauge. Preserve the
periodic log report for direct debugging, backed by the same snapshots.

In =boring-infra=, add one annotated metrics Service per DaemonSet selector and
annotate the existing collector Service for its metrics port/path. Keep all
Services ClusterIP-only. Do not enable generic Pod scraping, kube-state-metrics,
node-exporter, cAdvisor, Alertmanager, or a public metrics route.

Add one importable Grafana dashboard for pipeline health: scrape availability,
file/partial state, capture and export rates, drops/retries, queue pressure,
probe freshness and latency, and collector-to-Loki latency/failures. Panels
must distinguish cumulative counters from current gauges and avoid alerts on
an absolute file count. Alert-rule delivery remains out of scope while
Alertmanager is intentionally disabled.

logtail /metrics ----+
probe /metrics ------+--> Prometheus --> pipeline-health dashboard
collector /metrics --+

CRI files -> logtail -> OTLP -> collector -> Loki
             metrics            metrics
#+end_example

* Consequences

- Pipeline loss, pressure, and latency become queryable without scraping logs.
- Per-target series remain bounded; adding workloads does not multiply
  self-metric cardinality.
- Each package keeps local metric vocabulary and tests. A shared module becomes
  justified only if a second implementation or meaningful duplicated policy
  appears.
- HTTP listeners and registries add some binary size and memory. Their resource
  cost is measured during rollout and must remain small.
- Pod phase, restarts, requests, limits, capacity percentages, network, and
  storage remain absent. Those require a separate workload-state decision.

* Acceptance

- Registry tests verify names, types, units, bounded labels, counter behavior,
  gauge snapshots, and histogram observations for all three programs.
- Failure-path tests prove read, push, queue, watcher, OTLP, and Loki errors
  increment the intended bounded result without embedding error text.
- =/metrics= responds while healthy and remains private. =/healthz= and
  =/readyz= follow the documented lifecycle without depending on remote
  systems, and all three endpoints shut down with their process.
- Prometheus reports every collector, logtail, and probe target as =up= and can
  query each documented metric from both nodes where applicable.
- The dashboard imports and renders live data without relying on absent
  kube-state-metrics or capacity signals.
- Steady-state metric series stay below 100 per process and encoded scrape size
  stays below 64 KiB per target.
- Before/after ten-minute medians show no more than 5 MiB additional RSS or 5m
  additional CPU per Pod at idle; larger cost stops the rollout for review.
- Formatting, workspace tests, strict Clippy, image builds, Kustomize renders,
  and Kubernetes server-side dry-runs pass.
- The merged implementation publishes one sortable immutable tag for all three
  images. Flux policies select it, image automation commits exact tag+digest
  references, telemetry reconciles successfully, and all five workload Pods
  become Ready on the new revision.
