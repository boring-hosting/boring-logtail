* Status

Implemented and locally validated on 2026-08-03. Awaiting maintainer approval.

* Goal

Identify the Kubernetes container that produced a captured write with the
smallest honest path:

#+begin_example
WriteOperation.cgroup_id
  -> asynchronously maintained cgroup ID to runtime container ID snapshot
  -> asynchronously maintained node-scoped Pod snapshot keyed by exact container ID
  -> namespace, Pod name and UID, container name, container ID, and node
#+end_example

The event path performs only in-memory lookups. Missing identity is explicit and
never drops captured bytes.

* Decision

- Use the node-scoped Kubernetes Pod watch as the sole source of Kubernetes
  identity. Container status already carries the exact runtime-qualified
  container ID needed to join with the cgroup resolver.
- Remove CRI RuntimeService reconciliation, its container/sandbox join, and the
  CRI/Kubernetes merge. The added fallback does not justify a privileged runtime
  socket, a second identity authority, duplicated models, or merge policy.
- Keep the last Pod snapshot when the watch reports an error and mark it stale.
  Containers first observed while Kubernetes metadata is unavailable remain
  explicitly unresolved until the watch recovers.
- Keep only identity facts used by enrichment: node, namespace, Pod name and
  UID, container name, and exact runtime container ID.
- Remove restart/attempt and identity-tombstone fields. CRI creation attempt and
  Kubernetes restart count have different contracts, neither participates in
  the identity join, and the active production path never produced identity
  tombstones.
- Remove aggregate enrichment counters and their periodic diagnostics. The
  explicit per-event enrichment result remains the source of truth; counters
  can return later behind a deliberate metrics boundary if they become useful.
- Preserve the existing exact, unresolved, stale, and ambiguous enrichment
  outcomes. Do not guess from partial IDs or collapse ambiguity into a winner.

This decision supersedes the CRI cache and merge portions of
=spec/20260802-1300-application-write-kubernetes-watch.org=. That document
remains historical evidence for the application =write=/=writev= capture
decision and its validation results.

Implementation must not restore those files or overwrite unrelated working-tree

* Invariants

- Captured bytes survive missing, stale, or ambiguous Kubernetes metadata.
- The ring-buffer/event path performs no filesystem, network, Kubernetes, or
  runtime-socket I/O.
- Joins use the complete runtime-qualified container ID; no suffix or short-ID
  matching is introduced.
- Kubernetes list/watch remains restricted to =spec.nodeName= for the collector
  node with read-only Pod RBAC.
- Failure of the Kubernetes watch degrades enrichment, not capture.
- The collector no longer opens or mounts a container-runtime socket.
- eBPF programs and the shared kernel/userspace ABI do not change in this work.

* Non-goals

- Making metadata available for containers created during a Kubernetes
  control-plane outage.
- Adding another metadata fallback, owner resolution, labels, annotations, or
  application-name heuristics.
- Reworking cgroup discovery, its bounded retention behavior, capture sampling,
  syscall coverage, or the current output/export boundary.
- Splitting the workspace into more crates.
- Repairing the separately recorded eBPF verifier blocker in A7.
